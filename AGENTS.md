## Лабораторная работа №3 со звёздочкой

Полное условие находится в [lab_3_star.md](lab_3_star.md). Перед работой
сверяйся с ним: требования этого файла имеют приоритет при расхождении с
кратким обзором ниже.

### Архитектура моделей

- Общий контракт `IModel` задаёт `fit(features, target)` и
  `predict(features)`. `IRegressor` и `IClassifier` разделяют задачи;
  классификатор также предоставляет `predict_proba()` и отсортированный
  `classes()`.
- `DecisionStump` и CART используют общий `SplitFinder`. Он получает матрицу,
  отклики, индексы объектов узла, разрешённые признаки, критерий и ограничение
  размера листа; возвращает лучший `Split` или отсутствие допустимого
  разбиения. Пень вызывает поиск для всей выборки, CART — для каждого узла.
  Не дублируй сортировку и вычисление критерия в моделях.

### Матрица и срезы

- `Matrix` хранит числовые данные в `RowMajor` или `ColumnMajor` layout.
  `MatrixSlice<T>` — невладеющее представление строки или столбца с шагом;
  оно не копирует данные, а изменение через изменяемый срез меняет матрицу.
- Получай строку через `matrix(row, std::nullopt)`, столбец через
  `matrix(std::nullopt, column)`. Направление среза определяется аргументами,
  а не layout; оба направления поддерживаются при обоих layout.
- Индексные `operator()` у матрицы и среза не проверяют границы. Для
  проверяемого доступа используй `at()`. Не получай срез или ссылку из временной
  матрицы: срез не владеет буфером и живёт не дольше матрицы.
- `operator*()` / `as_span()` дают `std::span` только для непрерывного среза;
  неплотный срез остаётся доступен по индексу и бросает
  `NonContiguousSliceError` при попытке получить `span`. Не создавай скрытую
  копию ради непрерывности.

### CART: критерии, построение и владение

- В узле перебирай допустимые пороги по значениям признаков. Регрессия
  максимизирует `S_L²/n_L + S_R²/n_R`; классификация максимизирует
  `A_L/n_L + A_R/n_R`, где `A = Σ_c n_c²` — форма критерия Джини.
- Для одинаковой оценки выбирай меньший индекс признака, затем меньший порог.
  Между равными значениями порог не ставь. Используй `std::midpoint`; если
  результат округлился к правой границе, используй левое значение, чтобы
  разбиение `x <= threshold` совпало с оценённым разбиением.
- `SplitFinder` сортирует значения каждого рассматриваемого признака один раз
  на узел и обновляет агрегаты критерия за `O(1)` при перемещении объекта через
  кандидатный порог. Передавай индексы строк, не копируй подматрицы в рекурсии.
- Останавливай рост по достижении `max_depth`, при числе объектов ниже
  `min_samples_split`, одинаковых откликах либо отсутствии допустимого
  разбиения. `max_depth = 0` даёт корневой лист; `min_samples_split >= 2`,
  `min_samples_leaf >= 1`. В текущей реализации глубина выше 64 отклоняется.
- Регрессионный лист хранит среднее откликов. Классификационный лист хранит
  частоты классов в едином отсортированном порядке `classes()`; вероятности
  возвращаются в этом же порядке, а ничья выбирает меньшую метку.
- Корневой узел владеет деревом; `CartNode` владеет потомками через
  `std::unique_ptr`. У листа нет потомков, внутренний узел хранит признак,
  порог и обоих потомков. Не сохраняй ссылки на временные матрицы или срезы в
  обученном дереве.
- `CartTreeSummary` используется приложением для вывода количества узлов,
  листьев, фактической глубины и нескольких разбиений. Это часть интерфейса
  демонстрации, не меняй вычислительное поведение дерева ради форматирования.

### Сборка, запуск и тесты ЛР3

Из корня проекта выполни:

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Примеры запуска CART при наличии локального Bank Marketing CSV:

```powershell
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task regression --target age --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task classification --target y --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
```

В CTest зарегистрированы `lab1_tests`, `decision_stump_tests`,
`matrix_slice_tests`, `cart_tests`, `cart_audit_tests` и
`decision_stump_cli_tests`. Проверяй также, что сборка использует `-Wall -Wextra`
(в текущем CMake дополнительно `-Wpedantic`), а ASan/UBSan в Debug запускаются
только когда toolchain и runtime-библиотеки это поддерживают. Не считай
санитайзеры выполненными по факту их наличия в настройках: фиксируй реальный
результат запуска.
