## Назначение

Цель лабораторной работы — создать консольную программу для загрузки, анализа
и предобработки табличных данных. Проект написан на C++20. Код разделён на
консольное приложение и библиотеку с загрузкой CSV, расчётом статистики и
преобразованием данных.

Программа читает CSV, определяет тип каждого столбца, показывает сводку по
пропускам, позволяет интерактивно просматривать статистику и гистограммы, а
перед выходом по запросу формирует матрицу числовых признаков, сохраняет её в
CSV и бинарный файл и сравнивает бинарный файл с повторно загруженными данными.

## Набор данных

Используется **Bank Marketing**, вариант `bank-additional.csv` из набора UCI
Machine Learning Repository: [страница датасета UCI](https://archive.ics.uci.edu/dataset/222/bank%2Bmarketing).
В описании UCI этот вариант содержит 4 119 строк наблюдений, случайно выбранных
из полного `bank-additional-full.csv`, и 20 входных переменных. В файле также
есть целевой столбец `y`, поэтому в CSV всего 21 столбец.

Исходный файл находится по пути
`bank-additional/bank-additional/bank-additional.csv`. Это текстовый CSV с
заголовком и разделителем `;`. Значения полей могут быть заключены в двойные
кавычки. Среди данных есть числовые и категориальные признаки о клиентах,
контактах и результатах маркетинговых кампаний, а также целевой ответ `y` о
подписке на срочный вклад. Строка `unknown` встречается в категориальных
значениях и в загрузчике считается обозначением пропуска.

В исходном CSV 4 119 записей и 21 столбец с заголовком. Программа не выделяет
`y` в отдельную целевую переменную: она загружает и предобрабатывает его так же,
как остальные столбцы.

- **Стандартная библиотека C++** — контейнеры, строки, потоки, файловая система,
  алгоритмы, `std::optional`, `std::span` и другие используемые средства.

Отдельные системные библиотеки для работы программы не подключены. Конфигурация
проекта не добавляет AddressSanitizer или UndefinedBehaviorSanitizer.

## Запуск и параметры командной строки

При запуске без параметров используется путь к CSV, сформированный относительно
корня проекта (на один уровень выше каталога `src`):
`bank-additional/bank-additional/bank-additional.csv`. Путь вывода по умолчанию
также строится относительно исходника и равен `bank-additional-processed.csv`.
Рядом с этим CSV программа создаёт бинарный файл с тем же базовым именем и
расширением `.bin`.

В PowerShell программу можно запустить из корня проекта так:

```powershell
.\build\lab1.exe
```

При необходимости задайте пути явно. В примерах используется имеющееся в проекте
расположение входного файла; кавычки позволяют передавать пути с пробелами.

```powershell
.\build\lab1.exe --help
.\build\lab1.exe --input ".\bank-additional\bank-additional\bank-additional.csv" --output ".\result.csv"
.\build\lab1.exe --input ".\bank-additional\bank-additional\bank-additional.csv" --bins 20 --fill mean --scale standard --encode ordinal --output ".\bank-prepared.csv"
```

После загрузки программа показывает сводку и запрашивает индекс столбца для
анализа. Введите `-1`, чтобы завершить просмотр и получить предложение сохранить
предобработанный датасет. Положительный ответ — `y`, `Y`, `д` или `Д`.

### Заполнение пропусков

В `--fill` задаётся способ для числовых признаков:

- `mean` — заменить каждый пропуск средним арифметическим непустых исходных
  значений: \(\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i\).
- `median` — использовать медиану исходных значений, то есть квантиль `q50`.
  Она меньше зависит от крайних значений, чем среднее.
- `zero` — подставить `0` независимо от значений столбца.

Статистика для среднего и медианы считается до подстановки. Если числовой столбец
полностью пуст при выборе `mean` или `median`, обработка завершается ошибкой
`числовой признак ... полностью пустой`. Стратегия `zero` может заполнить такой
столбец. Пропуски категориальных признаков во всех вариантах заполняются строкой
`__MISSING__`; отдельного CLI-параметра для категориального заполнения нет.

### Масштабирование

`--scale` выбирает преобразование каждого числового столбца после заполнения:

- `minmax` — линейно переводит минимальное и максимальное значения в 0 и 1:
  \[x'=\frac{x-x_{\min}}{x_{\max}-x_{\min}}.\]
- `standard` — вычитает среднее и делит на стандартное отклонение:
  \[x'=\frac{x-\mu}{\sigma}.\]
  В реализации среднее и дисперсия вычисляются по заполненным значениям;
  дисперсия делится на число элементов столбца.
- `robust` — вычитает медиану и делит на межквартильный размах:
  \[x'=\frac{x-Q_{0.5}}{Q_{0.75}-Q_{0.25}}.\]
  Квантили вычисляются линейной интерполяцией по отсортированным значениям.

Если диапазон, стандартное отклонение или межквартильный размах равен нулю,
реализация заменяет все значения данного столбца нулями. Нормирование
пересчитывается внутри каждой предобработки по этому набору данных.

### Кодирование категорий

`--encode` управляет представлением категориальных столбцов:

- `onehot` — создаёт бинарный столбец для каждой категории: в строке категории
  стоит 1, в остальных строках 0. Имена имеют вид `имя_признака_категория`.
- `ordinal` — оставляет один столбец с целочисленными кодами категорий,
  представленными как `double`; имя столбца остаётся исходным.

В обоих режимах категории сортируются лексикографически. Кодирование начинается
с нуля; поэтому `__MISSING__` также получает обычный код или отдельный one-hot
столбец. Ordinal-коды задают числовое отношение между категориями, которого у
них может не быть в действительности. Это может влиять на модели, использующие
порядок или расстояние числовых значений; для моделей, трактующих категории как
номинальные, такое представление требует особой осторожности.

## Этапы работы программы

1. **Загрузка CSV.** Загрузчик использует заголовок, разделитель `;`, маркер
   пропуска `unknown` и наличие заголовка, заданные в `lab1.cpp`. Разбираются
   кавычки и удвоенные кавычки внутри поля. Пустые строки файла пропускаются.
   Число полей сверяется с заголовком; ошибка содержит номер строки.
2. **Определение типов.** Пропущенные значения пропускаются при проверке. Если
   все непустые значения столбца разбираются как числа — столбец числовой; иначе
   категориальный. Полностью пустой столбец становится категориальным.
3. **Обнаружение пропусков.** Точное значение `unknown` записывается как пустое
   `std::optional`. Другие строки, включая пустое поле, не являются маркером
   пропуска.
4. **Сводка датасета.** Приложение выводит число строк, число загруженных
   столбцов, имя и тип каждого столбца, количество пропусков по каждому столбцу,
   где они есть, и общую сумму.
5. **Выбор признака.** Интерактивный цикл ждёт индекс столбца или `-1`. Ввод,
   который не является одним целым числом, и индекс вне диапазона обрабатываются
   сообщением и не завершают цикл.
6. **Статистика.** Вычисляется статистика исходного столбца; пропуски не
   участвуют. Категории выводятся в лексикографическом порядке.
7. **Гистограмма.** Для числового столбца используется число интервалов из
   `--bins`; для категориального выводится частота каждой категории. Постоянный
   числовой столбец отображается одним интервалом.
8. **Заполнение.** При подтверждении сохранения числовые пропуски заполняются
   выбранной стратегией, категориальные — `__MISSING__`.
9. **Масштабирование.** Заполненные числовые столбцы независимо преобразуются
   выбранной стратегией.
10. **Кодирование категорий.** Строковые категории кодируются one-hot или
    ordinal способом.
11. **Матрица признаков.** Результат — плотная матрица `double` по строкам и
    список имён столбцов результата. При one-hot число столбцов увеличивается;
    числовые столбцы сохраняют свои имена.
12. **Сохранение.** Матрица записывается в CSV и в бинарный файл. Бинарный файл
    тут же загружается обратно; сравниваются имена и все значения с исходным
    результатом, после чего печатаются размеры файлов в байтах.

## Методы статистики и предобработки

Для числового признака реализованы: число пропусков и непустых значений,
минимум, максимум, среднее арифметическое, генеральная дисперсия, квантили
`q05`, `q25`, `q50`, `q75`, `q95` и частоты числовой гистограммы. Дисперсия
вычисляется как
\[\operatorname{Var}(x)=\frac{1}{n}\sum_{i=1}^{n}(x_i-\bar{x})^2.\]
Квантили используют линейную интерполяцию: для отсортированных значений позиция
равна \(p(n-1)\), а результат интерполируется между соседними элементами.

Для категориального признака подсчитываются число пропусков, число непустых
значений и частота каждой категории. Отдельной частоты для пропусков в этой
статистике нет.

Гистограмма числового признака делит диапазон от минимума до максимума на
равные интервалы. Правая граница последнего интервала включает максимум.
Категориальная гистограмма представляет частоты категорий. Если числовых
значений нет, программа сообщает, что статистику рассчитать нельзя; если
категориальных значений нет, список категорий остаётся пустым.

## Файлы результатов и бинарный формат

`--output` задаёт имя CSV-результата. Записывается заголовок преобразованных
столбцов и значения матрицы; разделитель — `;`. Расширение CSV автоматически не
добавляется и не проверяется. Бинарное имя формируется заменой расширения пути
`--output` на `.bin`: например, `result.csv` даёт `result.bin`, а путь без
расширения — путь с расширением `.bin`.

Бинарный файл записывается в следующем порядке:

1. число строк как `uint64_t`;
2. число столбцов как `uint64_t`;
3. код порядка хранения как `uint32_t` (`1` означает row-major, то есть
   построчное хранение);
4. для каждого имени столбца — длина в байтах (`uint64_t`) и байты строки;
5. значения матрицы построчно как последовательности `double`.

При чтении сначала загружаются размеры и код порядка, выполняются проверки
заголовка и переполнения, затем выделяются контейнеры, читаются имена и значения.
После записи приложение загружает файл функцией `loadProcessedDatasetBinary` и
сравнивает имена и числа функцией `compareProcessedDatasets`.

Это учебный бинарный формат: он не задаёт порядок байтов, переносимый размер и
представление чисел, версию формата или контрольную сумму. Поэтому файл не
предназначен для надёжного обмена между платформами или долговременного хранения.

## Тесты

Тестовая программа `lab1_tests` зарегистрирована в CTest при включённом
`BUILD_TESTING` (по умолчанию CTest включён). Запуск из корня проекта:

```powershell
ctest --test-dir build --output-on-failure
```

Так как `ctest` также не добавлен в `PATH` текущего окружения, фактически
проверка запускалась через:

```powershell
& 'C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\ctest.exe' --test-dir build --output-on-failure
```

В проверенной среде CTest сообщил `100% tests passed, 0 tests failed` (1 тест).
Если любая проверка в тестовой программе обнаруживает ошибку, она выводит
сообщение и возвращает ненулевой код; CTest сообщает о таком завершении как о
провале.

Текущий набор проверяет:

- разбор простой строки CSV;
- определение числового и категориального типов;
- квантили на известном наборе значений;
- OneHot Encoding, имена и значения столбцов;
- сохранение бинарной матрицы, загрузку и сравнение;
- отказ при строке CSV с неправильным числом полей;
- стратегии MinMax, Standard и Robust Scaling;
- заполнение числовых пропусков средним;
- Ordinal Encoding.

## Ограничения и замечания

- Правило определения типа ограничено разбором чисел: числовая категория с
  числовыми метками также будет числовым столбцом. Порог числа уникальных
  значений не используется.
- Маркером пропуска является только строка `unknown`; пустые поля не считаются
  пропущенными. Загрузчик настроен под CSV с `;` и не является универсальным
  парсером произвольных форматов.
- Существующий парсер проверяет незакрытые кавычки и число полей, но не сообщает
  номер строки для незакрытой кавычки. Выходной CSV записывается без экранирования
  значений, содержащих разделитель или кавычки.
- Все столбцы файла, в том числе `y`, участвуют в предобработке. Для построения
  модели, где `y` должен быть целевым ответом, его нужно отделить от матрицы
  признаков; текущий код этого не делает.
- Для заполнения полностью пустого числового столбца средним или медианой
  подходящего значения нет, и обработка завершается ошибкой. При `zero` такой
  столбец заполняется нулями.
- В текущих настройках GCC не подключены ASan/UBSan: CMake-флаги содержат `-g`
  без опций санитайзеров, а GCC не находит `libasan.a` и `libubsan.a`. Запуск
  тестов с этими санитайзерами в данной конфигурации недоступен.
- Путь по умолчанию построен от `__FILE__`; его расположение зависит от пути к
  исходникам, записанного компилятором. При необходимости задайте `--input` и
  `--output` явно.

## Итог

Проект загружает Bank Marketing CSV, определяет типы столбцов, показывает
сводную и описательную статистику, строит текстовые гистограммы, заполняет
пропуски, масштабирует числовые данные, кодирует категории и сохраняет плотную
матрицу в CSV и учебный бинарный формат. Сборка и тесты управляются через CMake
и CTest.
