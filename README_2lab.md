# Лабораторная работа № 2*. Решающий пень

Условия ЛР2: [основной вариант](lab_2_standard.md) и
[вариант со звёздочкой](lab_2_star.md). В проекте реализован звёздочный вариант.

`DecisionStump` выбирает один числовой признак и порог. Для регрессии применяется
критерий дисперсии, для классификации — критерий Джини. Левый лист соответствует
условию `x <= threshold`, правый — `x > threshold`. Поиск разбиения выполняет
общий `SplitFinder`, который используется и CART в ЛР3.

## Алгоритм поиска порога

Для каждого признака `SplitFinder` сортирует индексы объектов по значению этого
признака. Значения матрицы не копируются и не переставляются. Для всех признаков
переиспользуется один буфер `sortedIds`; перед обработкой очередного признака он
сортируется заново.

Далее выполняется один проход по позициям от `0` до `n - 2`. Объекты
последовательно перемещаются из правой части в левую, а агрегаты обновляются до
проверки очередной границы. Если значения признака по обе стороны границы равны,
кандидатный порог пропускается. Иначе порог выбирается как `std::midpoint`
соседних значений. Если вычисление округлилось к правому значению, реализация
берёт левое значение, чтобы предсказание по правилу `x <= threshold` сохранило
рассмотренное разбиение.

При одинаковой оценке выбирается меньший индекс признака, затем меньший порог.
Порог считается допустимым, только если обе части удовлетворяют
`min_samples_leaf`.

## Критерии

### Регрессия

Для разбиения на левую и правую части ошибка предсказания средним равна

```text
SSE = Σ_L (y_i - mean_L)^2 + Σ_R (y_i - mean_R)^2
    = Q_all - (S_L^2 / n_L + S_R^2 / n_R),
```

где `S_L`, `S_R` — суммы откликов, `n_L`, `n_R` — размеры частей, а `Q_all =
Σ_i y_i^2` не зависит от порога. Поэтому минимизация SSE эквивалентна
максимизации

```text
G = S_L^2 / n_L + S_R^2 / n_R.
```

При перемещении объекта с откликом `y` достаточно увеличить `S_L` на `y` и
`n_L` на единицу. Правая сумма получается как общая сумма минус `S_L`, а
`n_R = n - n_L`. Оценка `G` после этого вычисляется за `O(1)`.

### Классификация

Для части размера `m` индекс Джини равен

```text
Gini = 1 - Σ_c (n_c / m)^2,
```

где `n_c` — число объектов класса `c`. Минимизируется взвешенный индекс
`n_L * Gini_L + n_R * Gini_R`. Если `A = Σ_c n_c^2`, то этот индекс равен
`n - (A_L / n_L + A_R / n_R)`. Так как `n` постоянно, критерий эквивалентен
максимизации

```text
H = A_L / n_L + A_R / n_R.
```

При переносе объекта класса `c` меняются только частоты этого класса. Если до
переноса в левой части было `a` объектов этого класса, `A_L` увеличивается на
`2a + 1`. Правая частота вычисляется как общая частота класса минус левая; если
до переноса справа было `b` объектов, `A_R` изменяется на `1 - 2b`. Размеры
частей также меняются на единицу. Поэтому обновление квадратов частот и оценка
`H` занимают `O(1)` независимо от числа классов: полный проход по классам на
каждом пороге не выполняется.

## Архитектура

`DecisionStump` реализует `IModel`. Его конструктор принимает `SplitCriterion`
(`Variance` для регрессии или `Gini` для классификации) и минимальный размер
листа. `fit()` создаёт индексы обучающих объектов, вызывает `SplitFinder`, а
затем вычисляет предсказание листьев: среднее для регрессии или наиболее частую
метку для классификации. Публичные `split_feature()` и `split_threshold()` дают
доступ к выбранному признаку и порогу после успешного обучения с разбиением.

`SplitFinder` отвечает за проверку входных данных, сортировку индексов,
инкрементальное обновление агрегатов и выбор лучшего `Split`. У него есть две
перегрузки `findBestSplit`:

- с `featureIds` — поиск только по переданному подмножеству признаков; этот
  интерфейс используется CART для разрешённых признаков узла;
- без `featureIds` — поиск по всем столбцам матрицы. Индексы признаков задаёт
  ленивый `std::views::iota`, без создания вектора размера числа признаков.

## Сложность

| Вариант | Время | Дополнительная память пня |
|---|---:|---:|
| Наивный перебор порогов | `O(d · n^2)` | зависит от реализации перебора |
| Реализованный поиск | `O(d · n log n)` | `O(n)` |

В наивном варианте для каждого из примерно `n` порогов заново просматриваются
все `n` объектов каждого признака. Здесь сортировка индексов выполняется один
раз на признак, после чего допустимые пороги проверяются одним линейным
проходом, а критерии обновляются за `O(1)`. Это снижает время с
`O(d · n^2)` до `O(d · n log n)`.

Для классификации число различных классов `K` не превышает число обучающих
объектов `n`: каждый класс в счётчиках встречается хотя бы у одного объекта.
Поэтому индексный буфер, массивы кодов классов и счётчики классов занимают
`O(n + K) = O(n)` дополнительной памяти. Матрица и целевые данные в эту оценку
не включаются.

## Тесты

Цель `decision_stump_tests` проверяет регрессию и классификацию, найденные
признак и порог, предсказания листьев, константный признак, `min_samples_leaf`,
повторяющиеся значения и ошибки контракта модели. Медленная наивная реализация
используется как эталон для сравнения с быстрым алгоритмом на 200 случайных
наборах отдельно для регрессии и классификации.

В `cart_audit_tests` проверяется, что перегрузка `SplitFinder` с подмножеством
признаков не выбирает запрещённый информативный признак. Эти тесты входят в
CTest. Этот README фиксирует существующие проверки, но не утверждает результат
их запуска.

## Вывод CLI

При запуске `decision_stump` CLI печатает сообщение об обучении модели и оценку
на тестовой выборке. Для регрессии выводятся MAE и RMSE, а также реальные и
предсказанные значения для первых десяти объектов (или всех, если их меньше).
Для классификации выводятся Accuracy, macro Precision, macro Recall, macro
F1-score, матрица ошибок и реальные и предсказанные классы для первых десяти
объектов (или всех, если их меньше). Вероятности классов печатаются только для
CART, поэтому в описании CLI для `DecisionStump` они не указаны.

Сборка и тесты из корня проекта:

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Примеры запуска при наличии локального Bank Marketing CSV
`bank-additional/bank-additional/bank-additional.csv` в корне проекта:

```powershell
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model decision_stump --task regression --target age
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model decision_stump --task classification --target y
```
