# Лабораторная работа № 3*. Дерево решений CART

## Цель и постановка задачи

Этот README описывает звёздочный трек ЛР3: построение CART для регрессии и
классификации с повторным использованием поиска разбиения решающего пня. Полное
условие трека содержится в `lab_3_star.md`. NW относится к альтернативному
основному треку; её код также присутствует в проекте.

Полные условия находятся в `lab_3_standard.md` и `lab_3_star.md`. Это два
альтернативных трека: основной посвящён NW, трек со звёздочкой — CART. Ниже
раздельно отмечено соответствие каждому треку.

Задача программы: прочитать табличный CSV, отделить целевой столбец, разбить
объекты на обучение и проверку, настроить предобработку по обучающим объектам,
обучить выбранную модель и оценить её на отложенной части.

## Архитектура

`src/lab1.cpp` содержит консольную точку входа и диспетчеризацию моделей;
`lab1_core` — общую библиотеку, определённую в `CMakeLists.txt`. Данные
подготавливают `prepareSupervisedDataset`, `splitDataset` и
`DatasetPreprocessor`. Числовые признаки передаются моделям как `Matrix`.

| Компонент | Назначение |
|---|---|
| `MatrixLayout`, `Matrix`, `MatrixSlice` | Плотная матрица `double` с построчным или постолбцовым хранением и невладеющими срезами строк/столбцов. |
| `IModel` | Общий контракт `fit(features, target)` / `predict(features)`. |
| `IRegressor` | Маркерный интерфейс регрессора, производный от `IModel`. |
| `IClassifier` | Интерфейс классификатора с `predict_proba` и отсортированным `classes`. |
| `IDistance` и реализации | Евклидово, Манхэттенское и Чебышёва расстояния. |
| `KnnSearch`, `KnnRegressor`, `KnnClassifier` | Общий поиск соседей и отдельная агрегация для двух типов задач. |
| `NadarayaWatsonSearch`, `NadarayaWatsonRegressor`, `NadarayaWatsonClassifier` | Общие данные и вычисление весов NW; модели регрессии и классификации. |
| `SplitFinder` | Поиск лучшего порогового разбиения по дисперсии или критерию Джини. |
| `CartRegressor`, `CartClassifier`, `CartNode` | Рекурсивное CART-дерево для числового отклика или классов. |

Общий интерфейс позволяет выбирать модели через `unique_ptr<IRegressor>` или
`unique_ptr<IClassifier>` в консольном приложении.

Для CART узел владеет детьми через `unique_ptr`. Метод `summary()` обходит
обученное дерево и возвращает число узлов/листьев, глубину (число рёбер от
корня до самого глубокого узла) и разбиения в порядке обхода слева направо.
CLI печатает первые пять разбиений с уровнем, именем признака и порогом.

## Алгоритмы

### k ближайших соседей (kNN)

Для объекта `x` выбираются индексы `N_k(x)` с наименьшим расстоянием
`d(x, x_i)`. В регрессии возвращается средневзвешенное значение:

\[
\hat y(x)=\frac{\sum_{i\in N_k(x)}w_i y_i}{\sum_{i\in N_k(x)}w_i}.
\]

Для равных весов `w_i=1`; для режима `distance` код использует
`w_i=1/d(x,x_i)`. При наличии совпадающих объектов с нулевым расстоянием вес
получают только они. В классификации выбирается класс с наибольшей суммой весов;
`predict_proba` возвращает нормированные доли весов по классам.

Параметры: `k`, метрика (`euclidean`, `manhattan`, `chebyshev`) и схема
взвешивания (`uniform`, `distance`).

### Ядерная регрессия Надаряя — Уотсона (NW)

Каждый обучающий объект участвует в ответе с весом гауссова ядра. В реализации
используется расстояние `d` и ширина окна `h`:

\[
K_h(x,x_i)=\exp\!\left(-\frac{d(x,x_i)^2}{2h^2}\right),\qquad
w_i(x)=\frac{K_h(x,x_i)}{\sum_j K_h(x,x_j)}.
\]

Для численного ответа:

\[
\hat y(x)=\sum_i w_i(x)y_i.
\]

Для классификации веса суммируются отдельно для каждого класса; максимальная
сумма задаёт прогноз, а нормированные суммы возвращаются как вероятности.
Вычисление весов в исходнике сдвигает экспоненты на минимальное расстояние, что
не меняет нормированный результат и помогает избежать численного переполнения.

Параметры: положительная конечная ширина окна `bandwidth` и метрика расстояния.

### CART

CART последовательно разбивает пространство порогом одного числового признака:
слева `x_j <= t`, справа `x_j > t`. Для регрессии порог выбирается по
уменьшению внутригрупповой суммы квадратов (эквивалентно максимизации
`S_L²/n_L + S_R²/n_R` при фиксированном узле). Предсказание листа — среднее
целевых значений.

Для классификации разбиение выбирается по критерию Джини. Для узла с долями
классов `p_c` нечистота равна `G=1-Σ_c p_c²`; алгоритм выбирает порог,
максимизирующий уменьшение взвешенной нечистоты (в коде сравнивается эквивалентный
критерий на частотах). Лист хранит распределение классов, прогноз — класс с
максимальной вероятностью.

Параметры: `max-depth`, `min-samples-split`, `min-samples-leaf`. В кратком
описании курса CART отнесён к звёздочной части ЛР3.

## Предобработка и разбиение

CLI по умолчанию использует медиану для числовых пропусков, отдельную категорию
для пропусков категориальных признаков, MinMax-масштабирование и OneHot-кодирование.
Также доступны числовое заполнение `mean`/`zero`, масштабирование `standard`/
`robust` и кодирование `ordinal`. Целевой столбец исключается из матрицы
признаков; пропуск в целевой переменной приводит к ошибке. Для классификации
`yes` и `no` отображаются в `1` и `0`.

Разбиение выполняется с test ratio `0.2` и seed `42`. Параметры предобработки
обучаются только на train, после чего одинаковое преобразование применяется к
train и test. В README проекта описан CSV `bank-additional.csv` на 4119
наблюдений. Для этого размера функция разбиения с указанными настройками даёт
3295 обучающих и 824 тестовых объекта (размер теста округляется).

## Сборка и запуск

Из корня проекта:

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Приложение называется `lab1` и принимает `--input` для CSV. Примеры запуска из
PowerShell после сборки:

```powershell
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model knn --task regression --target age --neighbors 5 --metric euclidean --weighting uniform
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model nw --task regression --target age --bandwidth 1.0 --metric euclidean
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task regression --target age --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model knn --task classification --target y --neighbors 5 --metric euclidean --weighting uniform
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model nw --task classification --target y --bandwidth 1.0 --metric euclidean
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task classification --target y --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
```

Общие параметры: `--model knn|nw|cart`, `--task classification|regression`,
`--target`, `--metric`, `--fill`, `--scale`, `--encode`. Параметры модели:
`--neighbors`, `--weighting`, `--bandwidth`, `--max-depth`,
`--min-samples-split`, `--min-samples-leaf`. Точные значения по умолчанию
задаются CLI в `src/lab1.cpp`: соответственно `5`, `uniform`, `1.0`, `5`, `2`,
`1`; метрика по умолчанию — `euclidean`, цель — `y`, задача — классификация.
Для получения актуальной встроенной справки используйте `--help`.

## Автоматические тесты

CMake подключает CTest и регистрирует шесть исполняемых целей:
`lab1_tests`, `decision_stump_tests`, `matrix_slice_tests`,
`nadaraya_watson_tests`, `cart_tests`, `cart_audit_tests`. Последний набор
проверяет детерминированное разрешение ничьих, порог между соседними
представимыми числами, подмножество признаков у `SplitFinder`, одинаковые
отклики, CART/stump для классификации, вероятности/порядок классов, повторный
fit, пустую тестовую выборку, ограничения размеров листа, многоуровневое дерево,
сводку дерева и одинаковые результаты для RowMajor/ColumnMajor.

### Оставшиеся проблемы

- Верхняя граница `max_depth=64` выбрана для защиты рекурсивного роста; это
  ограничение реализации, а не число из условия.
- В `AGENTS.md` ещё нужно записать самостоятельную часть и разрешённую помощь
  агента для выбранного трека.
- В этой среде ASan/UBSan проверить не удалось: GCC не находит соответствующие
  runtime-библиотеки. Обычная сборка использует Debug и предупреждения, но без
  sanitizer instrumentation.

## Выводы

После аудита CART останавливает рост по указанным условиям, выбирает
детерминированные пороги и сообщает структуру обученного дерева. Аудит-тесты
зарегистрированы в CTest. Аудит CART пунктов 1–10 и требований к выводу дерева
закрыт. Вне этих пунктов остаются актуализация `AGENTS.md` и проверка с
