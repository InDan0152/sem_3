# Лабораторная работа № 3*. Дерево CART

Текущая реализация соответствует звёздочному треку ЛР3. Полное условие находится в [lab_3_star.md](lab_3_star.md).

## Архитектура

- `IModel`, `IRegressor`, `IClassifier` задают общий интерфейс для регрессии и
  классификации.
- `Matrix` и невладеющий `MatrixSlice` предоставляют числовые данные.
- Один класс `DecisionStump` использует критерий `SplitCriterion::Variance` для
  регрессии или `SplitCriterion::Gini` для классификации. Он и
  `CartRegressor` / `CartClassifier` используют общий `SplitFinder`.
- CART узлы владеют потомками через `std::unique_ptr`. `summary()` возвращает
  количество узлов и листьев, фактическую глубину и описания разбиений.
- `IModel` задаёт общий вызов `fit()`/`predict()`. CLI выбирает конкретную
  реализацию при создании модели, а общие шаги обучения и предсказания вызываются
  через `IModel`. Дополнительный вывод и вероятности подключаются callback-функциями
  в ветви создания CART; после создания общего сценария приведений к типам моделей
  нет.

Пень и CART поддерживают классификацию и регрессию. CLI выбирает модель через
`--model decision_stump|cart`, а задачу через `--task classification|regression`.
Остальные настройки предобработки и загрузки данных сохранены.

## Критерии разбиения

В каждом узле `SplitFinder` ищет признак и порог, максимизирующие оценку
разбиения. Для регрессии используется

```text
G = S_L² / n_L + S_R² / n_R,
```

где `S_L`, `S_R` — суммы целевых значений в дочерних частях, а `n_L`, `n_R` —
их размеры. Минимизация SSE относительно предсказания средним эквивалентна
максимизации `G`, поскольку сумма квадратов всех целевых значений не зависит от
порога.

Для классификации применяется форма критерия Джини, максимизируется

```text
H = A_L / n_L + A_R / n_R,    A = Σ_c n_c²,
```

где `n_c` — число объектов класса `c` в части. При перемещении объекта
`SplitFinder` обновляет агрегат квадратов частот затронутого класса за `O(1)`;
правые частоты берутся как общие минус левые.

## Рост дерева и ничьи

Узел остаётся листом, если выполнено хотя бы одно условие:

- все его отклики равны (для классификации — все метки одного класса);
- достигнут `max_depth`;
- объектов меньше `min_samples_split`;
- `min_samples_leaf` не позволяет сформировать обе части;
- `SplitFinder` не нашёл допустимое разбиение.

Глубина корня равна 0; `max_depth = 0` оставляет дерево из одного листа.
Текущая реализация отклоняет глубину больше 64. Регрессионный лист предсказывает
среднее откликов. Классификационный лист хранит вероятности по общему
возрастающему порядку `classes()`. При равных вероятностях выбирается меньшая
метка класса.

Порог рассматривается только между соседними различными значениями признака.
Используется `std::midpoint`; если результат округлился к правой границе, берётся
левая, чтобы маршрут `x <= threshold` соответствовал оценённому разбиению.
При равной оценке `SplitFinder` выбирает меньший индекс признака, а затем меньший
порог. Сравнение оценок в реализации точное (`score == bestScore`).

## Общий поиск разбиения и сложность

`DecisionStump` вызывает перегрузку `SplitFinder::findBestSplit` для всех
признаков. CART передаёт индексы объектов текущего узла и разрешённые признаки.
В обоих случаях сортируются индексы строк, а не копии данных матрицы; пороги
просматриваются последовательным проходом с инкрементальным обновлением
агрегатов. CART повторяет поиск отдельно для каждого узла и распределяет между
детьми индексы объектов.

Обозначим через `N` число обучающих объектов во всей матрице, через `s` — число
объектов в рассматриваемом узле, через `d` — число признаков, через `K_node` —
число классов в узле, а через `K_global` — число классов всей обучающей выборки.
Классы кодируются только для `objectIds` этого поиска и хранятся в том же
переиспользуемом буфере, что и индексы объектов. Поэтому дополнительной
инициализации массива размера `N` при обработке узла нет. Построение локального
словаря классов занимает `O(s log(K_node + 1))`, сортировки и проход по порогам —
`O(d · s log s)`. Так как `K_node ≤ s`, а `d ≥ 1`, итоговая стоимость поиска узла
составляет `O(d · s log s)`, не считая начальной проверки всей выборки
`O(N · d)` в `fit()`. Для всего дерева стоимость суммируется по внутренним узлам;
для корня `s = N`, поиск занимает `O(d · N log N)`.

Дополнительная память одного поиска — `O(s + K_node)` для буфера объектов и
счётчиков классов; поскольку `K_node ≤ s`, это `O(s)`. Рабочая память построения
дерева включает дочерние векторы индексов: каждый активный кадр рекурсии держит
два вектора, каждый резервирует ёмкость размера текущего узла. Для максимальной
глубины `D` рабочие индексы в худшем случае занимают `O(N · (D + 1))`. Реализация
ограничивает `D ≤ 64`, поэтому при этом фиксированном ограничении оценка равна
`O(N)`. Список признаков и временное кодирование классов добавляют `O(d + N)`,
так что рабочая память построения CART — `O(N + d)` с учётом лимита глубины.

Само дерево хранит `M` узлов; у регрессора это `O(M)` памяти, у классификатора —
`O(M · K_global)`, поскольку каждый узел хранит вектор вероятностей длины
`K_global`, включая нули для классов, отсутствующих в этом узле. Полная память
дерева классификатора вместе с рабочими данными построения оценивается как
`O(N · (D + 1) + d + M · K_global)`, регрессора — как
`O(N · (D + 1) + d + M)`. Эти оценки не включают исходную матрицу и целевые
значения.

## Численные ограничения

В `fit()` и при предсказании проверяются конечность признаков и целевых значений.
Регрессионные суммы и оценки накапливаются в `long double`, предсказания
регрессионных листьев переводятся обратно в `double`. Оценка разбиения и значение
регрессионного листа проверяются на конечность; при выходе за представимый
диапазон выбрасывается `InvalidParameterError`. Диапазон `long double` зависит от
платформы, поэтому это не гарантия точной работы для любых конечных `double`.
Для порога используется `std::midpoint`, чтобы не вычислять потенциально
переполняемую сумму `a + b`.

## Сборка и запуск

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Примеры запуска:

```powershell
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model decision_stump --task regression --target age
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task regression --target age --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model decision_stump --task classification --target y
.\build\lab1.exe --input .\bank-additional\bank-additional\bank-additional.csv --model cart --task classification --target y --max-depth 5 --min-samples-split 2 --min-samples-leaf 1
```

CTest регистрирует `lab1_tests`, `decision_stump_tests`, `matrix_slice_tests`,
`cart_tests`, `cart_audit_tests` и `decision_stump_cli_tests`. Общие тесты
ЛР1/матрицы и проверки пня/CART оставлены для проверки текущей реализации.
